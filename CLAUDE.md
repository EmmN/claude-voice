# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Voice for Claude Code on WSL2: spoken replies (Stop hook → Piper TTS), a wake-phrase listener ("hey claude" by
default, `VOICE_WAKE`; spotted with faster-whisper, or a bundled openWakeWord model such as `hey_jarvis`) that delivers dictated requests to plain `claude` sessions in any
distro through per-session inbox files and an `asyncRewake` Stop hook, a three-layer "brain" (fixed phrases in `dispatch`, a local ollama model in `brain`, and optionally a Claude session made Jarvis's brain with `/speak jarvis`), and a `/speak` skill. Everything is small bash
scripts in `bin/` with embedded Python heredocs; only `bin/listen.py` is a standalone Python file. README.md is the
user-facing reference (commands, env vars, tuning) and has the flow diagrams.

## Development

There is no build or linter. Tests: `tests/run` (or `tests/run test_dispatch`) — Python `unittest`, offline and isolated: each test gets a throwaway HOME / VOICE_HOME / VOICE_SHARED, `CLAUDE_VOICE_PLATFORM=linux`, `JARVIS_BRAIN=0` (no ollama), no audio; fixtures in `tests/helpers.py` (`add_session`, `claude_session_file`, `transcript`, `project`). They run the real scripts as black boxes and import listen.py: `Jarvis` (the conversation logic, built by `main()` from the real Source/Whisper/wake model) has seams — `say_prompt`, `play_interruptible`, `beep`, `dispatch`, `run_tool` — that `tests/test_conversation.py` replaces, with a fake mic of loud/quiet frames and scripted transcripts. Stand-ins: `fake_audio()` (piper/ffmpeg on PATH), `fake_ollama()` (HTTP server; brain, ai_pick, speechify honour `OLLAMA_URL`), a fake venv python for the daemon tests. `listen --stop` only touches listeners of its own `VOICE_LOCK`, so the suite never stops your real one. GitHub Actions runs them on every push. Add a test with every behaviour change or bug fix; most bugs of this project's history (routing phrasings, the re-wake, the stray "one", the wrong print line) would have been caught by one. Two install shapes: a dev link (`~/.claude-voice` → this checkout, made when
`install.sh` runs from the repo with no `~/.claude-voice` yet), where edits are live, or a normal curl install
(`~/.claude-voice` is its own clone), where changes reach it only after push + `claude-voice update`. `~/.local/bin/*`
link into `~/.claude-voice/bin/` either way. Restart the listener with `claude-voice stop && claude-voice start` after
changing `listen.py`; hook *registration* changes need a new Claude session or `/hooks`.

Ways to exercise pieces in isolation:

- `bin/dispatch --text "tell docs site to check the logs"` — parse/route a transcript without sending (prints `sent <name> | <body>`, `focus <name> [| <body>]`, `list <n> | …`, `broadcast <n> | …`, `cancel`, or `nomatch <reason>`); `--state` gives the listener's JSON. Point `VOICE_SHARED` at a scratch dir with fake registry entries to test routing.
- `bin/listen --from-wav file.wav --no-ack` — run the listener pipeline on a 16 kHz mono wav instead of the mic (build one with piper + ffmpeg: "Hey Jarvis.", 1 s silence, the request, 4 s silence).
- `echo '{"session_id":"<sid>"}' | bin/hook-inbox` with the voice flag set — the waiter alone; drop text in the inbox file and it exits 2 with it on stderr.
- `echo "…" | bin/speechify` — the ollama rewrite alone; `SPEECHIFY_DISABLE=1` skips it.
- `bin/say "text"` — TTS + playback; `bin/mic-test` — record 5 s and play back.
- `echo '{"session_id":"…","transcript_path":"…"}' | bin/hook-stop` — the Stop hook (exits silently unless voice is on for that session id).
- `bin/setup` — idempotent re-install (venv, links, skill copy, hook registration in `~/.claude/settings.json`).
- `dev/bench-models <model> …` — score ollama models on the brain (20 labelled sentences against a fixture registry) and on speechify, through the real scripts; stop the listener first. Default model is `gemma4:e4b` (100 %, 0.46 s with ollama 0.35, fully in VRAM); `qwen3.5:4b` 90 %, 0.57 s; `qwen3.5:9b` 95 %, 1.29 s.
- `~/.claude/voice/listen.log` — `log(msg, level)` in listen.py: date, level (WARN/ERROR), `[conversation id]`; each conversation ends with a `done:` line of step timings (`Timer`). The capture's ffmpeg stderr is read by a thread that only counts the WSLg dts-jitter noise; conversation exceptions are logged with a traceback and the loop continues. `listen --daemon` rotates the log past `VOICE_LOG_MAX` (5 MB).
- `~/.claude/voice/speech.log` — `speech_log` (lib.sh) timestamps each reply's steps in hook-stop, speechify and say.
- `bash -n bin/<script>` for a syntax check.

## Architecture

**Platform layer** (`bin/lib.sh`): `PLATFORM` = wsl / mac / linux (`CLAUDE_VOICE_PLATFORM` overrides; `CLAUDE_VOICE_PLATFORM=mac . bin/lib.sh; echo $VOICE_SHARED $VOICE_LOCK` is the cheap check of the Mac paths). Only `VOICE_SHARED`/`VOICE_LOCK` are platform-specific; everything else derives from them. Portable helpers: `pid_alive` (no `/proc` on macOS; Python heredocs use `os.kill(pid, 0)`), `mtime`, `mtime_ns` (Python fallback), `now_ns`, `newer_or_equal`, `mic_input_args`; on macOS lib.sh prepends Homebrew's coreutils gnubin so the GNU `stat`/`date`/`timeout` calls work, also inside hooks. `play` picks Windows player / WSLg, `afplay` or PulseAudio; `listen.py` reads `PLATFORM` (exported by lib.sh) for `mic_input()` and `mic_safe()` (mic may stay open during playback: always off WSL, on WSL only with the Windows player) and `load_whisper()` (faster-whisper, or mlx with `VOICE_WHISPER_BACKEND=mlx`). The capture ffmpeg carries `-metadata comment=claude-voice-capture` for `listen --stop`. Scripts must stay bash 3.2 compatible (macOS /bin/bash): no `${x,,}`, `declare -A`, `mapfile`, `&>>`. Untested on a real Mac.

**Two state locations** (defined in `bin/lib.sh`, which every script sources):

- `VOICE_HOME=~/.claude/voice` — per-distro: `sessions/<session_id>` empty flag files (voice on), `muted`, `current_session` (last session to submit a prompt, written by `hook-prompt`), `focus` (default dispatch target), `listen.pid`/`listen.log`.
- `VOICE_SHARED=/mnt/c/Users/<you>/.claude-voice` — Windows-side, shared by all distros: `sessions/<distro>__<session_id>.json` registry written by `/speak on` (`name, distro, session_id, pid, cwd`; tmux-hosted `claude-session` entries are `<distro>__<name>.json` with a `tmux` field) and `inbox/<distro>__<session_id>.msg` (pending spoken requests). Plus `VOICE_LOCK=/mnt/c/Users/<you>/.claude-voice.lock`, the cross-distro flock that serializes speech.

**Spoken-reply flow:** `hook-prompt` (UserPromptSubmit) records `current_session` and, for prompts starting `/speak`, runs `voice <sub> <sid>` and returns the result as `systemMessage` — the hook does the toggling; `skills/speak/SKILL.md` only confirms. `hook-stop` (Stop, async) checks the flag file, takes the reply from the hook input's `last_assistant_message` (the transcript JSONL is only a fallback: it may not contain the final message yet when the hook fires, which made replies play a turn late), prefixes "From <name>:" when >1 session has voice on, and detaches `speechify | say`. `speechify` by default (`SPEECHIFY_MODE=read`) is just `strip-markdown`: the reply word for word, cleaned for speech (paths → file names, snake_case → words, ids/hashes/URLs dropped, "30 s" → seconds); `SPEECHIFY_MODE=summary` retells it with ollama (slow: ~25 s for 300 words) and falls back to `strip-markdown` when the reply is short, ollama is down, or output is empty. `say` synthesizes with Piper, takes the flock and calls `play`, which hands the WAV to the Windows-side player (`windows/player.ps1`, a hidden long-running PowerShell copied to `<shared>/player.ps1`; queue `<shared>/play/`, heartbeat `player.alive`, `player.quit` asks it to exit) and waits for it to delete the file; without the player it plays via `ffmpeg -f pulse` → WSLg (never ffplay). WSLg breaks playback up while a recording stream is open in the same distro, which is why speech goes out through Windows.

**Hands-free flow:** `/speak on` → `voice on` → `register_session` (lib.sh) writes the registry entry from Claude's `~/.claude/sessions/<pid>.json` (name, pid) and sets focus; `hook-prompt` refreshes it every prompt. `hook-inbox` is a second Stop hook with `asyncRewake: true`: after each turn it polls `inbox/<distro>__<sid>.msg` and, when `dispatch` appends a request, prints it to stderr (asking Claude to begin with a `🎤 You said: "…"` line, which hook-stop drops from the speech; the hook entry's `rewakeSummary` labels the collapsed line) and exits 2, which wakes the idle session (one waiter per session via `sessions/.<sid>.waiter`; it exits when voice goes off or Claude's pid vanishes). `hook-end` (SessionEnd) calls `unregister_session`; `sessions` prunes entries whose distro is stopped or whose pid no longer maps to that session id.

Wake: `PhraseSpotter` (listen.py) segments the stream into speech bursts (0.45 s quiet ends one, 2.6 s caps it), transcribes each with the main Whisper model primed with the phrase, and fuzzy-matches the first words (difflib ≥ 0.75, up to two lead-in words); a burst whose phrase is followed by more words goes straight into `converse(first_text=…)` (no greeting), one cut off mid-speech into `converse(first_frames=…, strip=True)` (keeps recording, then drops the phrase from the transcript). A `VOICE_WAKE` that names a bundled openWakeWord model (`<name>_v0.1.onnx`) uses that instead; it fires about a second after the word, so the main loop keeps a 2.5 s `ring` of frames and `request_after_wake()` uses it: `keeps_talking()` listens up to 1.2 s (speech after a pause, or speech at the end of the window = still talking → `converse(first_frames=ring+more, strip=True)`); otherwise the ring is transcribed and `strip_wake()` (phrase or its last word, within the first 8 words) yields the request, or nothing → greeting. Settings: `~/.claude/voice/config` (KEY=value; lib.sh exports each unless already in the environment; `claude-voice config` edits it and restarts the listener).

`listen` (wrapper: `--daemon` runs it under a bash supervisor loop that restarts it 3 s after any exit, pid/log, venv `nvidia/*/lib` on `LD_LIBRARY_PATH`) runs `listen.py`: 80 ms frames (a capture that hits EOF is reopened, never ends the loop; only when the Windows player is down, the capture is closed while the lock is held by someone else and around own prompts: `Source.pause/resume`) → wake word → if the lock is held, touch `<lock>.stop` (barge-in) → take the lock (3 s max) → `prompt()` a cached Piper wav ("OK, <focus>…" or the session list, from `dispatch --state`) → record until `VOICE_SILENCE` → "Got it." → Whisper (primed with the session names) → `dispatch` → cached ack → release. Up to two rounds when the first answer only picks a session. When no fixed phrase matches, `dispatch` asks `brain` (ollama chat, think=false, JSON asked for in the prompt because qwen3.5 ignores `format` with think=false): `route` (session name or focus), `answer` (dispatch prints `answer | <text>`, the listener speaks it uncached), or `escalate` (delivered to the session in `<shared>/jarvis_brain` with a "Question for Jarvis" preamble, printed `ask <name>`; without one, a spoken hint). brain failure → focus. Facts come from the registry entries, which `hook-prompt` (`status=busy`, `last_prompt`) and `hook-stop` (`status=idle`, `last_reply`) update via `register_session sid key=value…` (it merges). The listener runs `brain --warm` at start and on every wake. Speech vs noise: `is_voice()` = level above the threshold AND `speech_prob()` (Silero VAD from openWakeWord, 0.3 ms per frame) ≥ `VOICE_VAD`; used by record_request, keeps_talking, PhraseSpotter and (≥ 0.6, four frames running) barge-in over prompts. Without the model (system python in tests, or missing) it is loudness only. `record_request` uses a speech threshold of 3× the noise floor, clamped to 120–900, where the floor only learns from background-level frames (not speech or played replies); the first answer after the session list may take `VOICE_FIRST_WAIT` (8 s), and a miss is logged with the peak level and said aloud. A wake runs `converse()`: the session list ("Which session: A or B?", or "OK, A…" with one session), then rounds of record → beep (`chime()`) → Whisper → dispatch. Until a session is named in the conversation, dispatch runs with `VOICE_NO_FOCUS=1` (with several sessions the stored focus is ignored, so an unnamed request gets "which session"); a bare name sets `picked` and asks what to do; a delivered request or an answer ends it, and `forget_wake()` then feeds openWakeWord 2 s of silence (reset() alone left the opening "hey Jarvis" in its audio buffer, so the next frames woke it again). Follow-ups are opt-in (`VOICE_FOLLOWUP=1`): `dispatch` touches `<shared>/awaiting/<key>` for every session it delivers to (not broadcasts); `hook-stop`, after `say` finishes, turns that into `<shared>/followup` (the session's spoken name, empty for the Jarvis brain), and the main loop, when the lock is free, starts `converse()` with "Anything else for <name>?" (ignored after 60 s; a wake deletes it). Cancel words include "no", "that's all", "I'm good", and short replies like "nothing right now, we're good" (unless they also contain an action verb). `speak()` drains the capture pipe after every own prompt and after each conversation (a reopened capture missed the start of your answer): otherwise the buffered audio of Jarvis's own voice is heard as your answer or as a wake word. `brain` answers only group-level questions (counts, which, busy/idle, time, greetings, few-shot examples in its prompt); an answer that talks about routing is turned into a route. While the lock is held by someone else (a reply playing), openWakeWord uses `VOICE_WAKE_THRESHOLD_PLAYING` (0.3) and logs near misses; `say` plays replies at `VOICE_REPLY_VOLUME` (0.6, ffmpeg volume filter). On a wake the listener creates `<shared>/listening` (removed when the conversation ends); `say`, after taking the lock, steps back while that mark is fresh (< 120 s), so a queued reply cannot grab the lock in the instant between the interrupt and the listener's acquire. With a Claude brain set, dispatch sends any request that resolves to no session (except an explicit switch) to the brain with a "Request for Jarvis" preamble instead of `nomatch which session`. `say` writes the text it plays to `<shared>/speaking`; `Jarvis.reply_says_wake_word()` then raises the wake threshold to 0.7 for that reply. `play_interruptible` judges barge-in only after the prompt has been audible for 10 frames, against its echo since then. `Source.frame()` ends a capture that delivered nothing for 2 s (WSLg stalls without EOF) so the reader thread reopens it. `say` keeps `VOICE_REPLY_GAP` (5 s) after the previous reply ended (`<shared>/last_reply_end`), releasing the lock while it waits. A wake that interrupts a reply (`interrupted` in handle_wake) looks for the wake word anywhere in the ring's transcript (`strip_wake(anywhere=True)`: the reply's own voice comes first) and, unless the conversation sent a request to a session (`request_sent`), writes "stop" at the end so the reply is dropped instead of replayed. A cancel whose words include stop / quiet / shut up / silence / enough / hush makes the listener write "stop" itself, so the reply it interrupted and the queued ones are dropped rather than replayed. The stop file's content is the reason: `voice stop` writes "stop" (say drops the reply, and queued ones skip); the listener writes "wake" (a wake during a reply) or "barge" (you talked over a prompt), and say then releases the lock and, when it gets the lock back, goes on from the start of the sentence it was cut in (`resume_at`: ffmpeg silencedetect finds the pauses piper leaves between sentences, `--sentence-silence` 0.3 s; up to 3 attempts). Fractional mtimes (`stat -c %.9Y`) are compared, so a replay starting in the same second is not cut again. `speak(…, interruptible=True)` plays prompts through `play` in the background while reading frames: 4 frames above max(threshold, 3× the running median of the prompt's echo) stop it ("barge") and the last few frames start the answer (`record_request(prefix=…)`). `dispatch` grammar: cancel words, list, switch/focus (optionally "… and <request>"), bare name, "for the X session", "tell/ask X", "all sessions", else focus; word-overlap name matching; delivery appends to the inbox file, or `tmux send-keys` for legacy `claude-session` entries (those have a `tmux` field). `say` synthesizes before queueing on the lock, plays with a length+5 s timeout and drops a stalled clip (SAPI only without Piper: PowerShell can take 15 s to start).

**Opening/closing by voice:** `dispatch` turns "start a session in <project> [called X] [on the Y distro] [and ask it to …]" into `open <dir> | <name> | <request> | <distro>` (folders from `VOICE_PROJECTS`, listed in the target distro over `wsl.exe --exec`) and "close the X session" into `close <name> | <key>` (only when every word names a session); it never acts itself. The listener's `confirm()` asks, and only a clear yes runs `session-open` (writes a self-deleting launch script into `<shared>/launch/`, opens a tab: `wt.exe -w 0 new-tab … wsl.exe -d <distro> -- bash -lic ". <script>"` (interactive, so ~/.bashrc — nvm, node tools — loads; the script is sourced so its cd triggers the user's hooks; it deletes itself by literal path, never `$0`) — no `;` in wt arguments; macOS `osascript`; `CLAUDE_VOICE_CLAUDE` swaps claude for a stand-in in tests) or `session-close` (SIGTERM, SIGKILL after 8 s, remote via `wsl.exe --exec kill`, then unregisters). `hook-start` (SessionStart) turns `CLAUDE_VOICE_AUTO=1` into `voice on`, retrying until Claude's own session file exists.

**Dispatch details:** before matching, a session name Whisper split into words ("web shop 7c") is put back together, a misheard leading "tell" (stell, tel, tall, tale) is read as tell when a session name follows, "<name>, <request>" addresses that session, and a sentence ending in never mind / forget it / cancel that / scratch that is a cancel. A brain `route` only goes to a session the sentence actually names (`mentioned()`); otherwise it falls through to the focus or the Claude brain. Listener: a transcript that is only (part of) the wake word gets "Yes?" (`is_wake_fragment`), `nomatch empty request` gets "What should I tell it?". The prompt cache key includes the Piper voice and speed (a changed SAY_VOICE never replays old prompts) and `warm_prompts()` renders `COMMON_PROMPTS` in the background at start. Answers are recorded through `Jarvis.listen_answer()`: `record_request` raises `MicDead` when 2 s pass with nothing above `VOICE_DEAD_MIC_LEVEL` (digital silence: a stalled or broken capture), and the listener reopens the capture and asks again once ("Sorry, I lost you…"), then gives up with "please check the microphone"; an empty transcript is asked again once. Near misses (wake score ≥ 0.3) are logged in idle too. Battery: the listener touches `<shared>/listener.alive` every ~30 s; `player.ps1` polls every 250 ms and quits after `VOICE_PLAYER_IDLE` without clips while that heartbeat is stale; setup no longer starts the player; hook-inbox polls once a second with builtins; ollama keep-alive is 5 min. `claude-voice home <dir>` scaffolds a private brain folder from `templates/home-CLAUDE.md`; personal notes, session names and mishearings belong there, never in this repo (its docs, comments and tests use only made-up names).

**Past sessions:** `recent-sessions` greps the transcripts once for `custom-title`/`ai-title` lines and each file's first `cwd` (0.5 s over ~1 GB), ranks by fuzzy title match (difflib per word, minus 0.01 per extra title word) or recency, marks `open` from live `~/.claude/sessions/*.json`, and `--top-projects` counts sessions per folder over 30 days. `dispatch` emits `history | [rows]`, `resume | row`, `pickproject | {top, name, request, distro}`; the brain also has `past` / `resume` / `open` / `close` actions for free-form session commands, which dispatch rewrites into its canonical sentence and dispatches again with `DISPATCH_NESTED=1` (no second brain call; a "project" that is no folder becomes title words, a "name" that is a folder becomes the project), so with no voice session the brain still runs; when words fail, `ai_pick()` asks the ollama model to choose an index from folder names or the last 150 titles (confirmation follows). The listener reads lists with `humanize()`/`when()`, `pick()`s by number (only when no title words were said) or title words, and resumes via `session-open --resume <id>`.

**Front doors:** `claude-voice` (start/stop/status/register/session/mic-test/log/update; `register` = `setup --no-listener`) and `voice` (per-session on/off/status/mute/unmute, jarvis on|off, stop, sessions, focus, listen, mic-test) are thin dispatchers over the scripts above.

## Conventions

- Scripts locate siblings with `HERE="$(cd "$(dirname "$(readlink -f "$0")")" && pwd)"` because they run via `~/.local/bin` symlinks; keep that pattern in new scripts.
- Scripts use `set -uo pipefail` (no `-e`, except `setup`/`install.sh`); hooks must always `exit 0` quickly and never block the turn (the one exception is `hook-inbox`: async + `asyncRewake`, it waits by design and exits 2 to deliver).
- New user-facing commands need a link line in `bin/setup` step 3 and a row in the README Commands table; new env knobs go in the README Tuning table.
- `bin/setup`'s hook registration removes prior entries matching the command path before appending, so re-running is safe; preserve that when changing hooks.
